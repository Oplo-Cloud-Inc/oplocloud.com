Open Roxan

Built to bechecked.

Plain statements about what Roxan stores, what it sends, how it is stopped from acting on its own, and what we are not claiming.

What Roxan keeps, and where

Roxan works while you are away, so it cannot live only in your browser. What it keeps is stored in your account on Roxan’s servers: your chats, notes, goals, routines, panels, specialties, Handoffs, projects, rules, settings, and a log of what it did. Each account has storage of its own, apart from every other account’s.

Files you attach are not kept. Roxan reads an attached file for the message it came with, and keeps only its name.

You type your invite code once. Roxan trades it for a sign-in cookie that scripts on the page cannot read, which lasts four weeks, and does not keep the code in your browser.

The Vault is the one exception to all of this. It is stored in this browser, sealed, and Oplo never has the key. If you clear this browser’s site data, the Vault is gone.

What leaves Roxan’s servers

To write a reply, Roxan sends a language-model provider the recent conversation; the notes chosen for that message, with the names they are about; your goals, your routines and the rules you have set; the specialties that fit; the project’s notes; how you want Roxan to sound, whether learning is on, and the time; and any files attached to that message.

When Roxan uses its cloud computer, the command it writes goes to a code-sandbox service that runs it on a private machine, and what the command prints comes back to Roxan. The machine holds nothing of yours: no notes, files or sign-ins. Roxan is told to keep your private details out of commands, and a command that holds a card number is refused. The machine is thrown away when the task ends.

A background run sends what it needs to do its job: the routine’s instruction, and for a watch the page’s text before and after it changed.

Roxan’s servers check your session, apply limits and pass the request on. Roxan does not write the content of messages to its logs. The provider’s own handling of that content is governed by its terms, which Roxan cannot change.

Nothing from the Vault is ever part of a request. The code that sends requests does not contain the Vault’s code, and an automated test fails if that changes. Anything else you type into a message does go to the provider. Roxan refuses a message that looks like a card number.

What Roxan does on its own

Reminders, routines and watches run on Roxan’s servers at the time you set, with nobody watching. A run can use only the tools Roxan has, under the same rules as a chat, and with two more: a run that has read a web page or a file must ask before it starts or changes a routine, keeps a note, saves a specialty or saves a Handoff, and a run nobody is watching cannot keep a note about you without asking.

Routines run one at a time, at most 30 background runs and 300 chat messages a day. A routine that fails three times in a row pauses itself and tells you, and one button in Settings pauses everything Roxan does on its own. The limits stop a mistake, or a page that tries to keep Roxan busy, from running up a cost.

Roxan messages you on its own only when what it found is new and worth your attention. The same message is not sent twice in a day, you choose how often it may speak first and when it is quiet, and when it holds a message back the reason is in Activity.

How actions are controlled

Roxan can only use the tools it has been given, and each tool has a fixed shape that is checked before anything happens. Text written by the model never counts as permission.

  • Every tool belongs to one capability, and you decide for each: allow it, have Roxan ask first, or turn it off. Reading web pages can have a rule for a single website. Where more than one rule applies, the strictest wins.
  • Out of the box, goals, panels, ideas, reminders and the cloud computer go through, and starting a routine, forgetting a note and saving a Handoff ask first.
  • An approval card shows exactly what will happen, and what runs is what the card showed. An unanswered approval expires after 7 days (3 days when a background run asked), and one approval allows one action.
  • If anything is missing, unclear or expired, the action does not run. Roxan is told when something has not happened, and says an action is done only after it has.
  • None of Roxan’s tools buys anything, sends email or messages, signs in anywhere, or runs a web browser.
  • A Handoff is a written task. Saving one runs nothing, because no computer is connected, and it is marked done only when you say you did it.
  • With learning on, a short note that rests on what you wrote is kept at once, shown in the conversation with an Undo. With learning off, Roxan asks first.

Untrusted content

Web pages, files you attach and anything else Roxan reads are data. Roxan is told so, and the app enforces it: once a run has read a page or a file or used the cloud computer, starting or changing a routine, keeping a note, saving a specialty or saving a Handoff asks first, whatever your rules say. A note is kept straight away only if it rests on what you wrote yourself, and one that looks like a password, an ID number, or a medical or money detail waits for your yes. A card number is never kept.

Roxan reads public websites only. It does not sign in, and it refuses an address that names a machine, a private network, a port or a login, including when a redirect lands on one. Replies are shown as text and links; nothing in a reply is executed.

The cloud computer is a separate throwaway machine, and from it Roxan can reach the wider internet, not only public pages. It holds nothing of yours. Each task is limited to a few short commands and a set time, there is a daily limit, and you can set it to ask first or turn it off under Access.

The Vault

Secured by OploCloud. Each item is sealed in your browser before it is saved: AES-256-GCM, with a key made from your passphrase and a random salt using PBKDF2 with SHA-256 and 600,000 rounds. The browser creates the key so that it cannot be exported, and it is held in memory only while the vault is open. Every item has its own random nonce, and its place is bound into the seal, so an item cannot be swapped or altered without opening failing. The vault locks after five idle minutes and when you leave its page, and it is never part of an export.

There is no reset, because nobody but you has the passphrase. Forget it and the items cannot be recovered.

What this does not cover:

  • The code that seals the vault is delivered by this website each time it loads, so you are trusting the code we serve, as with any web app.
  • While the vault is open, anything on this device that can read your screen or your browser, such as malware or a hostile extension, could read it too.
  • Anyone who gets a copy of this browser’s data can try passphrases offline. Four or more random words resist that; a short one does not.
  • No computer is connected yet, so nothing is filled into any website from the vault. That is the next step.

Your controls

Read, edit or delete any note, goal, routine, panel, specialty or Handoff, and turn learning off. Set a rule for each thing Roxan can do, and pause everything it does on its own. Delete a chat, or a project (its chats stay, as side chats). Delete the Vault and everything sealed in it. Download everything Roxan keeps as one file (files you attached are not in it, since only their names are kept, and the Vault is left out), or delete everything in one step.

A note you forget stops being used at once. Roxan keeps its text under Removed in Memory, so it does not learn the same thing again, until you restore it or delete everything.

Deleting removes the data from Roxan’s storage straight away. Copies the hosting service keeps for recovery, if any, expire on its own schedule, which Roxan cannot change.

What is not claimed

  • Roxan has no security certifications or independent audits yet, the Vault included. “Secured by OploCloud” names the feature; it is not a certification.
  • Messages are not end-to-end encrypted. The provider has to read the text to answer it, and Roxan’s servers can read what they keep for you. Only the Vault is sealed against us.
  • Learning relies on a model’s judgement, so it can keep a note you did not want. That is why each is shown with an Undo.
  • A model can misread an instruction. Starting a routine asks first and shows what it will do, and a routine can use only the tools above, but it can still do something you did not mean inside them.
  • Roxan cannot use a web browser yet. A Handoff is a saved task, and none has been run for anyone.
  • A pop-up on your device while the tab is closed is not built yet. The message waits in the chat.
  • There are no Oplo Accounts yet, so access is by invite code. Anyone who holds your code can open your Roxan.
